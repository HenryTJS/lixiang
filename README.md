## 1. 数据集 A：主样本（016–020，内部疲劳机）

### 1.1 这是什么数据

- 5 Hz 正弦载荷疲劳试验，服役期**渐进损伤**（健康 → 退化 → 断裂）；016–019 峰/谷 = 10 / 1.0 kN，**020 为 8 / 0.8 kN**（故严格同工况只有 4 组）。
- 三源：光纤(FO) + 声发射(AE) + 应变；**10 Hz 统一时间轴**（采样率恒为 10 Hz，全组一致）。
- 块 = `EXT_BLOCK_PTS=500` 点 = **50 s = 250 个载荷循环**；失效锚 `b3` = 数据末端（≈99% 寿命）。

## 4. 数据集 D：phmdc（外部方法验证平台，8 件）

### 4.1 为什么要引入它

A/B/C 有一个共同硬伤：**没有损伤定量真值**（只有失效锚 / `n_f`）⇒ 定位与指标的"准确性"**永久不可评估**。
PHM2019 铝搭接件数据集（*Fatigue Crack Growth in Aluminum Lap-Joint*）用来补这一块。

| 它有而 A/B/C 都没有的                                 | 代价                                                |
| ----------------------------------------------------- | --------------------------------------------------- |
| ✅**原始波形**（20 MHz / 4000 点 / 200 µs）    | ❌ 铝 / 铆接 /**Lamb 波** ≠ 复材 / 加筋 / AE |
| ✅**定量真值**（光学实测**裂纹长度 mm**） | ❌ 试件仅**8** 个                             |
| ✅**精确循环锚** + 训练/验证划分                | ❌ 只给单对传感器 ⇒**无定位能力**            |

> ⚠️ **它不改变 A/B/C 的任何结论**（物理不同），也**不填补 ReMAP 的 NDT 真值缺口**。
> 唯一用途是回答「**这个损伤指标对不对**」—— 这是本项目一直无法回答的问题。

### 4.2 做了哪些工作

| 步                    | 做什么                                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **Step 0**      | 数据规整 +**8 项核对**（`time` 列重建、带通滤波、噪声下界标定、可用性复审）                                       |
| **Step 1**      | 32 特征 + LOSO 8 折 + 10 个对照臂                                                                                         |
| **Step 2**      | 波形级 DL（1D/STFT × 1/2 通道 × 2 种参考口径），**含 cuDNN 确定性锁定**                                           |
| **外推 / 预后** | T7–T8 用前半段预测后半段；增长律视界分层；`--equiv` 等损伤当量换算；`--anchor` 健康原点锚定                          |
| **统计验证**    | 标签置换检验（特征级 N=300 / CNN 级 N=30）、不确定性量化（单位=试件）、配对检验、**第二通道消融（4 个无信息对照）** |

### 4.3 取得哪些成果

| 步               | 结果                                                                                                                                                                                                                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Step 0** | `time` 列 **92/94 不可用**（被 Excel 量化成科学计数法）⇒ 重建 `t[i]=i×5×10⁻⁸ s`；带通 100–300 kHz 把重复性 corr **0.9545 → 0.9985**、relRMS 差 33.5% → 5.6%；**噪声下界 = 6%**（此后成为"是否真检出损伤"的硬标尺）；核对还**撤销**了"T5 不可用"的误判 |
| **Step 1** | 最优`linear+单调约束` RMSE **1.501 mm** / MAE 1.233 / 折内 rho 0.928；`rf+约束` 折内 rho **0.970**（量程 0–7.46 mm）                                                                                                                                                     |
| **Step 2** | 最优「2 通道 CNN + 约束」RMSE**1.692 mm** / MAE 1.410 / 折内 rho **0.934** / 零裂纹误报 **24%**                                                                                                                                                                         |
| **外推**   | **T7（等幅→等幅）** `lin_last2`/`lin_all` RMSE **0.668 / 0.830 mm**，可用；**T8 不可验证**（视界超出自检极限 1.8 倍）                                                                                                                                              |

**三条可复用的方法学结论**（这是引入该平台的**主要产出**）：

1. **对比 DL 与特征工程必须保证信息对等**。Step 1 最强的特征需要"看到健康基线"，而单通道 CNN 只看一个波形
   ⇒ 补上"相对参考波形的差值"通道后 RMSE **2.084 → 1.692**、零裂纹误报 **88% → 24%**。
   否则"DL 更差"只反映**输入设计缺陷**。
2. **增长律选型必须按视界分层**（负面结论：短视界选出的 Paris 律在长视界上爆炸）。
3. **物理约束层（保序投影 + 非负）在 4 个特征工程臂 + 10 个 DL 配置上全部有效**，
   且**降低** RMSE（而非通常的"牺牲精度换可解释性"）：因为本数据的裂纹确实单调增长，约束剔掉的是模型**抖动**。
   投影只用"按循环数排序"，**不用标签**，不构成泄漏。

**统计验证（补上"没有外部真值"的一部分缺口）**：

- 把裂纹标签在**试件内**随机置换后重跑**同一套 LOSO**，真实指标**全部低于置换分布的最小值**：
  特征级 `rf+mono` 真实 **1.845** vs 零分布最小 **1.984**（z=4.21，p<0.0033）；
  CNN 级 `cnn+mono` 真实 **1.718** vs 零分布最小 **2.185**（z=4.78，p<0.0323）；
  **折内 rho 从置换后的 ≈0.00 抬到 0.92** ⇒ 模型学到的是**真信号**，Step 1/2 的指标**不是过拟合**。
- **该检验能分辨臂的好坏（不是走过场）**：`linear+mono` 是唯一没压到分辨率下界的（300 次里有 3 次追平）
  ⇒ 岭回归那 2.247 里有一部分来自**拟合试件级偏置**而非裂纹信息；`rf` / `rf+mono` 的零分布完全够不到
  ⇒ 选 `rf+mono` 作最优臂**在统计上也站得住**。
- 🔴 **口径**：这**不是精度验证**。对外只能声称
  「方法在**有真值**的平台上被**标定**、在**无真值**数据上被**统计验证**」。

**第二通道消融（Step 6）—— 证明增益来自"信息"而非"容量"**

| 第 2 通道内容                               | RMSE            | 零裂纹误报    |
| ------------------------------------------- | --------------- | ------------- |
| **真实差值**                          | **1.692** | **24%** |
| `shuffle`（保留边缘分布、只破坏样本对应） | 2.037           | 81%           |
| `dup`（**参数量与真实完全相同**）   | 1.996           | —            |
| `zero`                                    | 1.968           | —            |
| `rand`                                    | 2.131           | —            |
| 单通道                                      | 2.084           | 82–88%       |

⇒ **四个无信息对照的零裂纹误报全部回到 81–88%（真实 24%，零重叠）**，
且 `shuffle` 与单通道**不可区分**（p=0.731）⇒ 2 通道的增益确实来自**信息**。
⚠️ 真实 vs `shuffle` 直接比较 p=0.092（边际）⇒ 结论**建立在零重叠与"与单通道不可区分"上，不靠单个 p 值**。

### 4.4 一个工程教训

**cuDNN 卷积反向默认非确定**：同代码同种子两次运行，逐折 RMSE 最大差 **0.171 mm**（T5 折）、
整体 1.697 ↔ 1.732。这是**所有"文档数字与产物不符"的根因**。
已加 `lock_determinism()`（`manual_seed` + `cudnn.deterministic` + `benchmark=False` + `use_deterministic_algorithms`），
验证两次运行产物**逐字节相同**，**成本为零**。

## 5. 数字大屏（dashboard）

### 5.1 做了什么

- **纯前端、零后端**：双击 `dashboard/index.html` 即可用；顶栏切换数据集 / 试件。
- **三套数据一站显示**：主样本 **11 组**（016-020 + 022-027）、L1 一批 **4 组**、L1 二批 **9 组**（共 24 组）。
- **页面区域**：顶栏（数据集/试件/台架信息/状态灯/时钟）、控制条、**损伤度仪表**（D 值 / 分级色环 / 三档刻度 / 剩余裕度）、
  **D(t) 趋势**（D + risk 曲线、阈值带、b2/b3 锚、论文 HI_F 灰色参考线、实时游标）、
  **分级预警**（三级灯 + 各级触发时刻 + 证据条）、**多源子面板**（AE / FBG / 应变 / 证据层分解）、
  **空间分布面板（仅 L1）**（偏离热图 + 当前块空间分布 vs 基线）、底栏（事件日志 + 通道健康表）。
- **在线语义**：新选一组数据时**看不到任何数据**，曲线从试验起点随回放生长；任意时刻只显示**当前及之前**的信息
  （阈值锚、预警灯、统计量都只在真实发生后才出现）；拖进度条 = 在该时刻重新开始观察。
- **操作**：开始/暂停、复位、回放倍率 30×–600×、进度拖拽、声音（分级不同音调）、`空格`/`←`/`→` 快捷键。

### 5.2 取得哪些成果

- 把「逐点流式的 D(t)」从**离线产物**变成**可回放、可演示、可核对的在线过程** —— 这是"在线"一词的**可视化证据**。
- 三套数据用**同一个前端**，只看顶栏切换 ⇒ 框架的"同框架、不同适配"被界面直接体现。
- L1 一批额外显示**论文 HI_F 灰色参考线**（离线参考），并标注 **D 早 N 个百分点** ⇒ 与复现结果可当场对照。
- 二批主指标为**离线复评 `HI_AE`**，仪表单位改为 `HI_AE (0–1)`、余量标签改为 `1 − HI_AE`（避免误用"损伤度/剩余裕度"语义）。

## 6. 自然语言 Agent（`agent/`）

### 6.1 做了什么

- **两个引擎，共用一套工具与约束**：

|                  | `agent/react.py` —— **真 Agent** | `agent/cli.py` + `core.py` —— 离线降级 |
| ---------------- | ------------------------------------------ | -------------------------------------------- |
| 谁决定调什么工具 | **LLM 自主决策**（function calling） | 关键词 + 编号正则                            |
| 调用形态         | **多步、单步可并行、可追加**         | 单轮、单工具                                 |
| 发现疑点后       | ✅ 自行追加查询再回答                      | ❌ 固定输出                                  |
| 依赖             | DeepSeek / OpenAI 兼容 API                 | **零依赖**，离线可跑                   |
| 用途             | 复杂提问、需要交叉验证的结论               | 演示兜底、无 key/无网、**无 LLM 基线** |

- **11 个工具**（只读产物，**不触发重算**）：`list_specimens` / `warning_status` / `stiffness` / `data_quality` / `compare` /
  `mechanism` / `localization` / `anomaly` / `l1_migration` / `doc_search` / **`maintenance`**（检修建议）。
- **PhysGuard：16 条物理约束规则**，把三级语义、闸门、能力边界、数据限制变成**可执行规则**，
  每次回答都校验、违规就拦截或强制标注；触发写 `agent/log/physguard_log.jsonl`，`--stats` 出量化统计。
- **回归测试**：`test_physguard.py` 23 用例 + `test_envfile.py` 22 用例（零依赖，可直接跑）。
- **消融实验框架**：`agent/eval/`（题集生成 + 三臂对照 `full` / `no_guard` / `bare` + 自动打分）。

**设计原则（四条）**：工具只读、**物理约束独立成层**（与模型解耦）、保留规则引擎（离线不缺失 + 作无 LLM 基线）、
**LLM 不接触数值**（数值/阈值/结论全部来自工具与规则，LLM 只决定"查什么、怎么讲"）。

**核心分工**：Agent 能力来自 LLM，但**结论可靠性不来自 LLM**。

### 6.2 取得哪些成果

- **三项功能均已实现**：状态查询、异常报警、**维修建议**。
- **真 Agent 实测（016 状态 + 可信性）**：2 轮 / 24.0 s，规则检查 72、拦截 0。LLM **自主**做了三件系统提示没要求的事：
  ① 第 1 步**并行**调 3 个工具（状态不止看 D(t)，还查刚度与数据质量）；
  ② 第 2 步**自行追加**文档检索（因 notes 提到"未解调""AE 无时间戳"，先查清概念对结论的影响）；
  ③ **独立交叉验证** —— 指出刚度 L≥10% 出现在 59.0% 寿命，与 D 的不可逆确认 59.9% 仅差 **0.9%**，
  据此判定「预警时刻不是标签拟合出来的」。
  它还**自行发现**一处我们未写明的疑点：L≥30% 与 L≥50% 落在同一寿命点（87%），
  推断为"末段幅值跳变式跨过 + 1% 块级分辨率不足"，并主动声明该点不可当精确时刻。
- **维修建议（示例二）**：给出 **A 立即处置**（D 达 L3 + 刚度 L≥0.50 两条独立路径同判），
  并主动说明"工具未给出具体区域，与其定位能力缺失一致"—— 把空字段读成了**能力边界证据**。
- **对抗测试（示例三）**：用户索要具体工艺方案与拧紧扭矩，它**拒绝**，并给出三层理由（工具的 `not_recommended` 项、
  文档检索零命中、"工艺方案的前提是损伤位置与范围，而 016 连定位都不可靠"）。
  更值得记录的是它自己的推论：*两个刚度阈值落在同一寿命点 ⇒ 016 经历的是**突发性刚度丧失**，这种整体性退化特征**本身就不支持"只修局部"的思路*** —— 工具输出里**没有任何一条**直接说"不支持局部修复"。
- **数据集 C 检修位置**：给出 X 区间 38.4–66.4 mm（质心 52.4 mm），并明确声明 **Y 向 σ≈46 mm 不可用于分区**；
  还自行指出一处口径分歧（无监督异常 15.5% 报警 vs D 检测起始 45.7%）。

### 6.3 一条可写进论文的方法学教训

> **做消融实验时，领域知识必须只能从自变量进入模型** ——
> 系统提示、上下文、工具描述里任何一句"常识性景"都会把干预效果抹平。
