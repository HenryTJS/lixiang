# 消融实验：物理约束层（PhysGuard）到底有没有用？

> 本目录是**可复现的实验**，不是演示脚本。目标是把「我们加了一层物理约束」这句话
> 变成一张能放进论文的**量化表格**。

## 1. 问题

Agent 回答 SHM 问题时，最大的风险不是"算错"，而是**说出物理上不可能或无证据支持的结论**：

| 例子 | 为什么是错的 |
| --- | --- |
| "016 的损伤位置在 X≈53 mm" | 主样本 AE **单通道、无到达时间** → 无 TDOA 定位能力 |
| "L1-49 损伤的 Y 坐标是 71.5 mm" | Y 向 σ≈46 mm（沿加筋条导波）→ 不可用于分区 |
| "016 建议打磨后补片胶接，扭矩 40 N·m" | 应变/AE 证据**推不出工艺方案** |
| "020 的刚度退化说明结构严重劣化" | 020 刚度**无信号**、应变幅值反而**单调下降** |
| "016 的预测误差 3.1%，精度很高" | b2 是**扩展标签**，不是独立物理真值 |

这类错误通用 LLM 必犯 —— 因为它在训练语料里学到的是"SHM 论文应该怎么写"，
而不是"这个数据集能支持什么结论"。

**待验证的假设**：把项目积累的物理先验显式注入回答过程，能显著降低这类越界。

## 2. 三臂设计

`react.py` 的 `--arm` 参数控制**模型能看到什么**。系统提示、工具集、模型、温度全部相同。

| 臂 | 工具回灌内容 | 对应现实中的做法 |
| --- | --- | --- |
| `full` | `notes` + **约束提示/违规** | 完整系统（本文方法） |
| `no_guard` | 仅 `notes` | 有证据链、无物理约束层 |
| `bare` | 两者都不给 | 裸工具输出 = **朴素 RAG Agent 基线** |

```
[full]     结果: {...}
           已知限制: 该组为 1 Hz 采样...；刚度无显著退化信号...
           数据来源: main/results/grade_stiff_traj.csv
           【物理约束提示·须在回答中说明】1 Hz 采样组不得声称高时间分辨率...

[no_guard] 结果: {...}
           已知限制: ...
           数据来源: ...

[bare]     结果: {...}
           数据来源: ...
```

**为什么要有 `no_guard` 这一臂**：`notes` 是工具契约的一部分（"这数据有什么毛病"），
`约束提示` 是规则层推出来的（"因此你不许下什么结论"）。两者常被混为一谈，
但**支持"物理约束层的必要性"这个论点的只有后者**。拆开才能看出贡献来自哪里。

## 3. 题集（`cases.json`，141 题）

题集的 ground truth **由 `gen_cases.py` 调 `tools.py` 派生**，不手录 ——
否则"你怎么知道 46.9% 是对的"就无法回答。工具读的是项目产物，产物可追溯到脚本与原始数据。

| 类别 | 数量 | 考察 |
| --- | --- | --- |
| 状态查询 | 44 | 能否取到正确数值 |
| **陷阱题** | **39** | **是否会说出物理上不可能/无证据支持的结论** |
| 检修建议 | 23 | 申报书 §4.1③ |
| 机制与定位 | 18 | 数据集 C 的扩展任务 |
| 不可回答 | 7 | 能否如实拒答而非编造 |
| 方法原理 | 7 | `doc_search` |
| 跨试件对比 | 3 | 多工具组合 |

陷阱题覆盖 22 类越界模式（每类 1–4 个变体）：无定位能力试件问位置、Y 方向、
工艺方案、间断组做定量、不存在的试件、把扩展标签当真值、跨口径比绝对值、
AE 事件速率、1 Hz 高分辨、覆盖不足、时间标定不可靠、RUL 未做、数据集混淆……

题集冻结在 `cases.json`，随代码一起提交，保证可复现。

> `--trap-only` 选出 `trap=true` 的 **46 题**（"陷阱题"类 39 + "不可回答"类 7），
> 这是信号最强、性价比最高的子集。

## 4. 指标（全部自动计算，无需人工评分）

| 指标 | 定义 | 期望方向 |
| --- | --- | --- |
| `fact` | 数值/关键词期望的命中率 | full ≥ 其它（**不应下降**） |
| `disclaim` | 限制声明合规率（陷阱题） | **full 明显更高** |
| `tool` | 必须调用的工具是否都调了 | full ≥ 其它 |
| `guard_err_rate` | **违规率**（核心）：用完整 PhysGuard 对最终回答独立评分 | **full 明显更低** |
| `guard_warn_rate` | 应标注未标注的比例 | full 更低 |
| 成本 | 耗时、token | 报告即可 |

三臂用**同一把尺子**（同一个 PhysGuard、`enable_log=False` 不污染生产日志）。

## 5. ⚠️ 方法学局限（必须写进论文）

1. **同源性偏置**：`guard_err_rate` 用的规则集与实验组的干预手段**是同一套**。
   规则既是"干预"又是"评分标准"，存在循环论证风险。
   → 因此结论**不宣称**"PhysGuard 让回答更正确"，只宣称
   "**在给定这组物理约束下，把它显式提供给模型能降低违反这些约束的比例**"。
   `fact` / `disclaim` / `tool` 三项与规则层独立，可作交叉印证。
2. **规则本身就是假设**：PhysGuard 的 16 条规则来自本项目的实测边界，
   **换数据集不成立**。这限制了结论的外部效度。
3. **自动打分的脆弱处**：`fact` 只检查"某个接近的数出现在答案里"，
   无法判断它是否被用在正确的语境；`disclaim` 只检查关键词。
   **`fab` 仍会捕获「派生量」**——模型自己算出的差值/比值
   （如「刚度 3.758 → 2.574，损失 31.5%」）合理但不在证据集合里，
   无法与真幻觉自动区分：若允许「任意两数之差」，候选数 C(n,2) 会让指标退化为恒 0。
   故必须**抽样人工复核**，并在论文中报告人机一致率。
   报告时优先用 **`fab率`**（未取证数值占比）而非 `fab任一`（≥1 个即计 1）。
4. **样本量**：141 题 × 3 臂 = 423 次。按类别分组后单格样本量偏小，
   只报**描述性统计**，不做显著性声称（或仅对 ALL 组做检验）。
5. **单模型单温度**：目前只测 `deepseek-flash`、temperature 0.2。
   结论不能外推到其它模型 —— 反过来，**"换模型后约束层是否仍有效"本身是好的后续实验**。

## 6. 运行

```bash
copy .env.example .env          # 把 DEEPSEEK_API_KEY 填进 .env（也可用环境变量 / --api-key）

# ① 生成/刷新题集（改了工具或口径后应重跑）
python agent/eval/gen_cases.py

# ② 试跑
python agent/eval/run_ablation.py --limit 6

# ③ 只跑陷阱题（信号最强、性价比最高）
python agent/eval/run_ablation.py --trap-only --workers 3

# ④ 全量（可中断续跑：已完成的 case×arm 会自动跳过）
python agent/eval/run_ablation.py --workers 4
```

**产物**

```
agent/eval/
├── gen_cases.py        题集生成器（ground truth 从工具派生）
├── cases.json          冻结的题集
├── run_ablation.py     三臂对照 + 打分 + 汇总
├── results/
│   ├── runs.jsonl      逐题逐臂原始记录（含完整回答，可续跑）
│   └── summary.csv     汇总表（论文表格直接来源）
└── README.md
```

`--fresh` 忽略历史重跑；`--category 陷阱题` / `--arms full bare` 可做子集实验。

**成本参考**：单次约 6–9 s、约 ¥0.03–0.06（`deepseek-flash`）。
全量 423 次 ≈ ¥15–25。

## 7. 当前结果（⚠️ **实验未完成，不得引用**）

截至 2026-09-15，只跑了两个**不完整**的小批次，**不构成任何结论**：

### v1（已作废）：48 题×3 臂

`results/v1_runs.jsonl` · `v1_summary.csv`

| 臂 | n | err率 | warn率 |
| --- | --- | --- | --- |
| full | 48 | 0.000 | 0.042 |
| no_guard | 48 | 0.000 | 0.062 |
| bare | 48 | 0.000 | 0.021 |

**144 次运行零违规、三臂无差异。但这不是"约束层无用"，而是设计错误：**

> **系统提示泄漏了物理约束。** 生产用 `SYSTEM_PROMPT` 里写了
> 「数据集 A = 主样本 016-020（**AE 无时间戳、单通道**；仅 016 应变为解调口径）」。
> 于是即使 `bare` 臂不给任何工具注释，模型**仍然知道主样本不能定位** ——
> 三臂的信息差被系统提示抹平了。

教训：**做消融时，领域知识只能从“自变量”进入模型。**
现在 `react.py` 提供了 `SYSTEM_PROMPT_NEUTRAL`（不含任何领域约束），
`run_ablation.py --prompt neutral` 默认使用它。

### v2（仅 8 题即中止）：`results/v2_runs.jsonl`

改用中性提示，并新增**与 PhysGuard 无关**的「编造数值率」指标后，仅试跑了 8 题×3 臂：

| 臂 | n | err率 | warn率 | fab率 | fab数 |
| --- | --- | --- | --- | --- | --- |
| full | 8 | 0.000 | 0.250 | 0.046 | 12 |
| no_guard | 8 | 0.000 | 0.125 | 0.099 | 21 |
| bare | 8 | 0.000 | 0.125 | 0.063 | 12 |

**n=8，且 fab 指标尚未抽样人工核对 —— 不能下任何结论。**
（仅能说：换用中性提示 + 编造率指标后，三臂终于出现可观测的差异，
指标体系方向上是可行的。）

### 恢复实验时要注意

1. **先核对 fab 指标**：用 `python agent/eval/show_runs.py v2_runs.jsonl`
   —— 它**按当前逻辑重算**并给每个"编造值"附上**上下文**，一眼即可判断
   是真幻觉还是派生量。
   > **2026-09-16 已修四个提取 bug**（修前 17/17 条误报、编造率 16.2%；
   > 修后 6/17 条、**1.48%**，残留全部为派生量）：
   > ① `evidence_numbers` 遍历 dict 时**跳过键**，导致 `{'L>=0.10': 59}` 的阈值丢失；
   > ② 百分数↔小数不等价（证据 `0.10` vs 回答「10%」）；
   > ③ 千分位逗号被切开（`31,442` → `31` + `442`）；
   > ④ 试件编号被当数字（`017` → `17.0`）。
   > 另将项目公开判据（D 三级 0.25/0.55/0.85、刚度档位 0.05/0.10/0.30/0.50）
   > 作为规范常量无条件允许。
   **未核对前不要把 fab 写进论文。**
2. 全量 141×3 = 423 次，约 ¥15–25、约 1 小时（`--workers 4`）。
3. 可中断续跑；已完成的 case×arm 自动跳过。
4. v1 的文件保留作为**反例教材**，不要删——它恰好记录了"系统提示污染消融"这个坑。
5. **不要在 `agent/eval/` 下新建与标准库同名的 `.py`**（`inspect.py`、`json.py`、
   `types.py` 之类）。Python 会把脚本所在目录放进 `sys.path[0]`，同名文件会
   **遮蔽标准库** —— 曾因 `inspect.py` 使 `numpy 2.x` 内部 `import inspect`
   被劫持、并在其顶层 `open(sys.argv[1])` 处崩溃。该文件已改名 `show_runs.py`，
   `run_ablation.py` / `gen_cases.py` 也已加 `sys.path` 防护。

```bash
python agent/eval/show_runs.py v2_runs.jsonl     # 抽样核对
python agent/eval/run_ablation.py --workers 4   # 续跑全量
```
