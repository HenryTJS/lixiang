
# 数据集路径与外接盘（2026-09-28）

**结论**：代码里**不含**任何数据绝对路径 —— 58 个脚本全部用 `os.path.dirname(__file__)` 自定位后走相对路径
（唯一例外 `l1/impact_truth_check.py` 的 `ROOT = r'd:\lixiang'` 已在本节修订）。因此**换盘不需要改代码**。

**做法**：仓库里保留目录结构，用 **Windows 目录联接（junction）** 把数据目录指向外接盘。
junction 不需要管理员权限、不占 D 盘空间；仓库内所有相对路径照旧有效。

**唯一入口**：仓库根 `paths.json`

| 键 | 含义 |
| --- | --- |
| `data_root` | 外接盘上的数据根（可被环境变量 `SHM_DATA_ROOT` 临时覆盖） |
| `items[].link` | 仓库内路径，支持通配 `*` `?` `[0-9]`（只匹配已存在的目录） |
| `items[].target` | `link` 含通配符 → 容器目录；不含通配符 → 精确目标 |

**命令**（在仓库根 `d:\lixiang` 执行）：

| 目的 | 命令 |
| --- | --- |
| 预览 / 自检（不改动） | `powershell -ExecutionPolicy Bypass -File tools\relink_data.ps1` |
| 搬迁并建联接 | `powershell -ExecutionPolicy Bypass -File tools\relink_data.ps1 -Migrate` |
| 换盘后重接 | 改 `paths.json` 的 `data_root` → 跑 `-Apply` |
| 拆链并还原数据 | `powershell -ExecutionPolicy Bypass -File tools\relink_data.ps1 -Unlink -Restore` |
| Python 侧查询 | `python run.py --paths`（或 `python shm/paths.py`，加 `--json` 出机器可读） |

**纳入搬迁的 50 条映射**（约 30.7 GB）：`l1/L1-*`（13 组）· `main/[0-9][0-9][0-9]`（001-027）·
`main/aligned` · `main/weak_labels` · `phmdc/T[1-8]`。
**不搬迁**（体量小或可重建）：`main/cache`（131.8 MB）、各 `results` / `figures`、
`dashboard/data`（19 MB）、`phmdc/results`。

**注意事项**

1. **外接盘未插时，这些目录表现为"空"** —— 脚本会报找不到文件。插回即恢复，**不需要重跑任何命令**
   （junction 一直指向同一路径）。
2. **盘符变了**（E: → F:）或**换了新盘**：先把数据拷到新位置，再改 `paths.json` 的 `data_root`，然后跑 `-Apply`。
   若目标不存在，脚本会**拒绝**建空链接（需 `-Force` 才建空目录）—— 这是防呆。
3. `-Migrate` 用 `robocopy /E /MOVE`（拷完再删源）。30 GB 视 USB 速度需数分钟至数十分钟，
   过程中**不要拔盘**。想更保守：先手工 `robocopy /E` 拷一份、核对后删源，再 `-Apply`。
4. 脚本**永不**对 junction 使用 `Remove-Item -Recurse`（那会递归进目标盘删数据），
   一律用 `rmdir`（不带 `/s`）只删联接本身。
5. **已实机验证**（临时目录）：预览 → 搬迁 → 经联接读写 → 拆链 → 还原，全链路通过；
   联接属性为 `Directory, ReparsePoint`，目标正确，还原后目录恢复为普通目录且外接盘副本按约定保留。
